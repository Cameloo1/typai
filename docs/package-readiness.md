# Package Readiness

Typai is package-ready for local packing and install smoke tests, but it is not
published to npm yet.

## Local Dry Run

Run:

```sh
pnpm pack:dry
```

This runs `npm pack --dry-run` for:

- `@typai/core`
- `@typai/contenteditable`
- `@typai/textarea`

The dry run reports tarball file contents without writing package tarballs.

## Local Tarballs

Run:

```sh
pnpm pack:local
```

This creates local tarballs under `.pack/` using `pnpm pack`. The `.pack/`
directory is generated output and must stay out of Git.

## Install Smoke

```sh
pnpm smoke:install
```

The smoke script:

- Builds local tarballs.
- Creates a temporary package outside the repo.
- Installs `@typai/core`, `@typai/contenteditable`, and `@typai/textarea` from
  tarballs.
- Imports `createTypaiCore`.
- Initializes Typai.
- Verifies `checkCompletedToken({ token: "teh" })` returns `the`.
- Imports `attachContenteditable`.
- Imports `attachTextarea`.
- Attaches `@typai/textarea` to a minimal textarea-like `EventTarget` with the
  overlay disabled.
- Dispatches a delimiter input for `teh ` and verifies the textarea value
  becomes `the `.

## Wasm Package Policy

`packages/core/pkg/` is generated by `pnpm --filter @typai/core build:wasm`.
It remains ignored in Git.

`@typai/core` runs `build:wasm` during `build`, and `prepack` runs `build`, so
the generated Wasm package is produced before local packing. The generated
`pkg/` directory is included in the `@typai/core` npm tarball through the
package `files` allowlist. Consumers should not need Rust, `wasm-pack`, or a C++
toolchain to install the packed package.

## Package Files Policy

`@typai/core` includes:

- `dist/`
- `pkg/`
- package metadata automatically included by npm

`@typai/contenteditable` includes:

- `dist/`
- package metadata automatically included by npm

`@typai/textarea` includes:

- `dist/`
- `README.md`
- package metadata automatically included by npm

`@typai/textarea` depends on `@typai/core` because the adapter requires an
initialized `TypaiCore` instance and uses shared core token/protected-span types.
It does not bundle a Wasm package of its own.

The packages intentionally exclude:

- `src/`
- `native/rust/target/`
- tests
- coverage
- Playwright reports
- test results
- examples
- `node_modules/`

## Textarea Package API

Consumers install the textarea adapter alongside core:

```sh
npm install @typai/core @typai/textarea
```

Use it with an initialized core:

```ts
import { createTypaiCore } from "@typai/core";
import { attachTextarea } from "@typai/textarea";

const typai = await createTypaiCore();
const detach = attachTextarea({
  textarea: document.querySelector("textarea")!,
  typai,
});
```

The adapter uses overlay mirror mode. `textarea.value` remains the source of
truth, native form submission reads that value, and the overlay never inserts
markup into the control.

## Not Published Yet

Do not run `npm publish` during Public Alpha Readiness. Do not add registry
credentials, release tags, or publish automation until the packaging surface and
license gates are explicitly approved.
